# AgentVille Branch-HQ Protocol

## 1. Principles

- The Branch determines Employee assignment, activity state, and condition. HQ stores and displays the results.
- Raw observations remain on the Branch.
- The canonical message schema is `packages/agentville/common/schemas/protocol-v1.schema.json` (JSON Schema 2020-12). Implementations conform to it.

## 2. Delivery

| Trigger | Message |
|---|---|
| Branch connects or reconnects to HQ | `snapshot` |
| State change on the Branch | `branch`, `agent`, `activity`, or `contractor` |
| Fixed interval | `heartbeat` |

- `seq` increases by one per message per Branch. It is never reused across Branch restarts; after a restart it may skip ahead.
- `event_at` is the time of the fact and is not ordered; message order is `seq`.
- On a gap in `seq`, HQ requests a new `snapshot`.
- Changes during disconnection are not queued. The `snapshot` on reconnect supersedes them.
- On receiving a `snapshot`, HQ replaces all stored state for that Branch.
- HQ marks a Branch `unreachable` when no message arrives within a multiple of the last `heartbeat.interval`, and when no message has arrived since HQ started.
- A `snapshot` that is not newer than HQ's state by `seq` and `sent_at` is answered with `need_snapshot`; a second such snapshot in answer is applied as a reset of a Branch whose clock moved back ([architecture.md](architecture.md) Section 4.1).

- Transport: HTTP(S) POST of `{"messages": [...]}` to `/api/v1/ingest/messages`; one Branch per batch, at most 1000 messages (a larger batch is rejected with 413). Response: `{"accepted", "duplicates", "stale", "need_snapshot"}`.

## 3. Envelope

| Field | Type | Description |
|---|---|---|
| `schema_version` | integer | Schema version, `1`. HQ validates every message against schema version 1 and rejects a batch containing any other version with 422. |
| `branch_id` | string | Host `id`. |
| `seq` | integer | Per-Branch sequence number. |
| `kind` | string | `snapshot`, `heartbeat`, `branch`, `agent`, `activity`, `contractor` |
| `event_at` | string | UTC time the fact occurred. |
| `sent_at` | string | UTC time the Branch sent the message. |
| `payload` | object | Kind-specific content. |

`(branch_id, seq)` uniquely identifies a message. HQ applies a duplicate message once.

## 4. Payloads

### 4.1 `agent`

Carries the full current state of one Employee.

| Field | Description |
|---|---|
| `agent_id` | Generated by the Branch on creation. Immutable. |
| `project_id` | Normalized remote URL, or hash of `(host, path)` for a repository without a remote. |
| `project_alias` | Project display name: the base name of the repository directory, or `Common Office`. |
| `provider` | e.g. `claude`, `codex` |
| `seat` | Seat number. |
| `alias` | Employee display name. Currently always null. |
| `presence` | `on_duty`, `off_duty`, `on_leave` |
| `presence_since` | UTC time of the last presence change. |
| `account_alias` | Account display name. |
| `model` | Model identifier. |
| `settings` | Runtime settings used for condition mapping, e.g. `{"effort": "high"}`. |
| `condition` | Condition determined by the Branch. |
| `instance` | Present only when on duty. See below. |

`instance`:

| Field | Description |
|---|---|
| `instance_id` | `AgentInstance` identifier. |
| `started_at` | UTC start time. |
| `runtime` | Runtime summary: `{"type": "tmux", "location": <tmux pane location reported by Claude Code>}`, `{"type": "shell"}`, `{"type": "app_server"}` (Codex thread on the app-server daemon), or `{"type": "rollout"}` (Codex run outside the daemon, observed from its rollout file only; [architecture.md](architecture.md) Section 3.4). The schema allows any object; these are the values sent. |

### 4.2 `activity`

| Field | Description |
|---|---|
| `agent_id` | Employee identifier. |
| `instance_id` | `AgentInstance` identifier. |
| `session_id` | Current provider session identifier. May change within an instance. |
| `state` | `working`, `thinking`, `waiting`, `idle`, `completed`, `error`, `limited`, `unknown` |
| `state_since` | UTC start time of the state. Used by the UI for idle progression. |
| `source` | `session_file`, `session_log`, `app_server`, `hook`, `process` |
| `confidence` | `high`, `medium`, `low`. Always `low` for a Codex run observed from its rollout file only. |
| `tool` | Tool name when `working`, e.g. `Bash`, `Edit`. |
| `reset_at` | Usage-limit reset time when `limited`, if known. |
| `workload` | Number of tool executions started in the last 5 minutes. A new `activity` is sent when it changes, including by time alone. |

### 4.3 `contractor`

| Field | Description |
|---|---|
| `contractor_id` | `AgentInstance` identifier of the Contractor. |
| `parent_instance_id` | `AgentInstance` identifier of the hiring Employee. |
| `provider` | May differ from the parent's provider. |
| `origin` | `in_process`, `child_process` |
| `status` | `hired`, `ended` |
| `state`, `state_since`, `tool` | Same as `activity`. |

### 4.4 `branch`

| Field | Description |
|---|---|
| `alias`, `country`, `time`, `location` | Host configuration values. |
| `thresholds` | Seconds, e.g. `{"phone": 300, "doze": 1800, "lounge": 3600, "leave": 604800}` |

### 4.5 `snapshot`

| Field | Description |
|---|---|
| `branch` | `branch` payload. |
| `agents` | `agent` payloads for all Employees. |
| `activities` | `activity` payloads for Employees on duty. |
| `contractors` | `contractor` payloads for active Contractors. |

### 4.6 `heartbeat`

| Field | Description |
|---|---|
| `interval` | Seconds until the next heartbeat. |

## 5. Data Minimization

The following are never sent to HQ:

- Local paths of repositories without a remote. For such a repository the `project_alias` (the directory base name) is sent and `project_id` is a hash of the host id and path; only the path is withheld.
- Account details other than `account_alias`.
- Provider subagent identifiers; `contractor_id` is derived from the parent instance and the provider subagent id.
- Process command-line arguments and environment variables.
- Tool arguments, file paths, prompt content.
- Details of `waiting` requests and `error` causes, including provider error and usage-limit fields (Claude `error`, `apiError`, `errorDetails`, `quotaLimits` other than the reset time; Codex `task_complete.error`). A usage-limit reset time is sent only as `reset_at`.

The Employee `alias` is currently always null, so no Employee display name is sent.
